# Управление Kodi с проверяемым результатом

Новый entrypoint: `src/reliable_server.py`. Это MIT-форк
`dgoo2308/kodi-mcp-server`, база `eabc93edb078c5392734da0acdd180dc87db619f`.
Прежний HTTP entrypoint сохранён для совместимости; для новой установки
используется только новый ограниченный набор инструментов.

`uv sync --locked` создаёт venv по `uv.lock`. Запуск:

```sh
KODI_RPC_HOST=127.0.0.1 KODI_RPC_PORT=9090 .venv/bin/python src/reliable_server.py
```

Kodi raw TCP не имеет пароля. Включать его можно только на loopback, с
`services.esallinterfaces=false`. Для удалённого подключения используйте
стандартный OpenSSH local forwarding с проверкой host key, а не открытый
порт Kodi в LAN/Internet. HTTP, OAuth и shell не входят в этот entrypoint.
Доступ к SSH задаётся клиентом вне публичного проекта. Локальные медиа
разрешены в `/media` и `/mnt`; другие корни задаются `KODI_MEDIA_ROOTS` через `:`.

Инструменты:

- `kodi_capabilities`, `kodi_state`: реальная версия/introspection,
  информация о медиа, таймере, скорости, доступных дорожках, GUI и декодере.
- `kodi_library_search`, `kodi_library_details`: поиск возвращает точные ID;
  несколько совпадений не запускают первый найденный фильм автоматически.
- `kodi_open`: movie/episode ID, HTTP(S) media URL или YouTube plugin URL;
  `resume=false` начинает сначала, `true` продолжает, число задаёт проценты.
  ACK отдельно от `av_started` и `progressing`. Наблюдение физического экрана
  этим инструментом не подразумевается.
- `kodi_pause`/`kodi_resume`: явный `play=false`/`true`, повтор не переключает
  состояние. `kodi_seek`: абсолютные/относительные секунды с проверкой границ.
- `kodi_queue`: get/add/insert/remove/swap/clear/goto, проверка позиций;
  `kodi_tracks`: только реально доступные индексы аудио/субтитров.
- `kodi_input`, `kodi_gui`: ограниченные кнопки и окна; shell/admin/builtins
  произвольного вида не публикуются.
- `kodi_youtube_browse`, `kodi_youtube_play`: установленное дополнение
  `plugin.video.youtube`. Дополнение, его зависимости и необходимая Google
  авторизация/API-конфигурация устанавливаются отдельно официальным способом.

Питание телевизора, HDMI-CEC и общая громкость системы принадлежат Home
Assistant. Kodi volume не подменяет системную громкость.

Транспорт обрабатывает фрагментированный UTF-8, слитые JSON и события. При
потере связи отправленная операция считается неоднозначной и не повторяется;
следующее независимое чтение подключается заново. Перед повтором изменения
очереди агент обязан проверить её фактический состав. Подписанные HTTP URL
не выдаются в результатах. Встроенный HTTP server и небезопасные upstream
default credentials для этого entrypoint не используются.

`make test check`: mock-проверки повторной паузы/продолжения, неоднозначного
поиска, перемотки, индексов дорожек, ошибок очереди, ACK без воспроизведения,
offline/reconnect и streaming JSON. Тестовые TCP-сокеты только loopback.

Ограничения: отсутствие JSONRPC-события не выдаётся за успех; screenshot
проверяется по introspection и не обещается для всех Kodi. Синхронизация очереди
с внешним пультом не транзакционна: перед записью проверяется актуальная длина,
а внешние изменения между проверкой и записью Kodi может отклонить. Физические
звук/картинку и совместимость оконного backend нужно принимать на устройстве.
